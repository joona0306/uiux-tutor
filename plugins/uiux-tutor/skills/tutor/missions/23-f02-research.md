# 23. F02. 서비스 분석과 사용자 리서치 — 미션 예시

> 문서 미션: 결과는 Figma/FigJam 보드 또는 마크다운 문서(`research.md`)로 제출해요. 로그인·결제·개인정보 화면은 분석하지 않아요.

## 배우기 재료
- 핵심 개념
  - **기능 구조와 UX 플로우**: 기능 구조는 서비스의 기능을 큰 메뉴 → 작은 기능으로 나눈 나무 목록, UX 플로우는 목표까지 거치는 화면 순서(화살표)예요. 시계를 분해해 부품과 맞물리는 순서를 보는 일과 비슷해요.
  - **같은 자로 재는 경쟁 분석**: 서비스마다 다른 것을 보면 비교가 안 돼요. 기준(행)을 먼저 정하고 서비스(열)를 채워요. "편함" 대신 "클릭 2번"처럼 **세어 볼 수 있는 사실**을 써요.
  - **인사이트와 HMW**: 모은 말을 비슷한 것끼리 묶어 이름을 붙이면 인사이트, 그것을 "어떻게 하면 ~할 수 있을까?"로 바꾼 문장이 HMW 예요. 해결책(버튼 이름)은 넣지 않아요.
- 작은 따라 쓰기 (사이트와 상관없이 문서에 직접 써요)
  ```text
  서비스: 동네 도서관 앱
  ├─ 홈
  │  └─ 신간 목록
  ├─ 검색
  │  └─ 제목·저자 검색
  └─ 내 서재
  목표: 책 한 권 찾기
  홈 → (검색 탭) → 검색창 → (제목 입력) → 결과 목록 ⚠️ 정렬 버튼이 작음  (클릭 2번)
  ```
- 예상해 보기: 경쟁 분석표의 두 칸 "찾기: 편함" / "찾기: 2번 클릭(하단 탭 → 검색)" 중 다른 서비스와 비교할 수 있는 칸은 어느 쪽일까요? — 답: 뒤쪽이에요. "편함"의 기준은 사람마다 달라 비교가 안 되고, 클릭 수는 셀 수 있어요.
- 공식 문서: [Guide to FigJam (Figma)](https://help.figma.com/hc/en-us/articles/1500004362321-Guide-to-FigJam) (보드로 정리할 때)

| 미션 | 할 일 (고른 사이트의 구역에 맞춰 바꿔요) | 완료 기준 |
|---|---|---|
| F02-1 기본 구조 | 고른 사이트의 공개 화면을 직접 눌러 보며 [기능 구조]를 2단계 목록으로 쓰고, 핵심 목표(예: 마음에 드는 항목 찾아 담기) 하나의 UX 플로우를 적어요 | 1단계 메뉴 3개 이상, 각각 아래 2단계 기능이 있음 / 플로우에 화살표 6개 이상 / 헷갈린 곳에 ⚠️ 1개 이상과 이유 한 줄 / 클릭 수가 숫자로 적혀 있음 |
| F02-2 개념 적용 | 비슷한 서비스 2곳을 더 골라 3곳을 같은 기준으로 비교하는 표를 만들어요 | 서비스 3열 × 기준 6행에 빈 칸 없음 / "편함·깔끔함"만 쓴 칸이 없고 클릭 수·보이는 정보 개수 같은 사실로 적음 / 맨 오른쪽 "내 클론에 가져올 점" 칸이 모든 행에 있음 |
| F02-3 응용 | 지인 1~5명에게 쇼핑·이용 경험을 묻고(인터뷰) 인사이트 묶음과 HMW 를 써요. 인터뷰가 어려우면 고른 사이트를 직접 쓰며 막힌 순간을 `P0` 메모로 남겨도 돼요 | 질문 8개 중 "네/아니요"로 끝나는 질문·유도 질문이 없음(과거 행동을 묻는 문장) / 기록에 이름·연락처·얼굴 사진이 없고 `P1`~`P5` 번호만 있음 / 말 그대로의 인용문 3개 이상 / 인사이트 묶음 3개와 HMW 3개가 있고 HMW 에 버튼·화면 이름이 없음 |

## 힌트 재료
- 1단계: 개념 이름만 찾아봐요 — 기능 구조(feature tree), UX 플로우, 경쟁 분석, HMW. 보드로 그린다면 Figma 도움말 "Guide to FigJam" — https://help.figma.com/hc/en-us/articles/1500004362321-Guide-to-FigJam
- 2단계: ① 메뉴를 처음부터 끝까지 눌러 1단계를 쓰고 그 안의 기능을 2단계로 들여 쓰기 ② 목표를 정해 놓고 화면이 바뀔 때마다 누른 것과 함께 한 줄씩 적기 ③ 표는 기준을 먼저(행) 정하고 서비스(열)를 채우기 ④ 비슷한 인용문을 묶어 이름 붙이기 → 묶음마다 "어떻게 하면 …" 한 문장
- 3단계 예시(다른 주제):
  ```text
  인용: P1 "일정이 안 맞으면 그냥 창을 닫아요"   P3 "날짜를 바꾸려면 처음부터 다시 해요"
  인사이트: 날짜를 고치는 길이 너무 멀다
  HMW: 어떻게 하면 처음 온 손님이 날짜를 다시 고르기 쉽게 할 수 있을까?
  ```

## 자주 막히는 곳
- 표가 "좋음/나쁨"뿐이라 비교가 안 됨 → 클릭 수·보이는 정보 개수·걸린 시간처럼 셀 수 있는 사실로 바꿔요
- 인터뷰가 5분 만에 끝남 → "네/아니요" 질문이에요. "가장 최근에 … 한 때를 이야기해 주세요", "왜 그랬어요?"로 바꿔요
- 기록에 실명·전화번호가 있음 → 개인정보예요. `P1` 같은 번호로 바꾸고 원본은 지워요
