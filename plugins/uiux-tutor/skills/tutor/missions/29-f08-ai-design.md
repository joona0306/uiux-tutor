# 29. F08. AI 디자인 도구 활용 — 미션 예시

> AI 에는 이름·연락처·얼굴 사진 같은 개인정보를 넣지 않아요(인터뷰 기록은 `P1` 번호만). 쓴 AI 는 모두 기록표에 남기고, 결과는 원래 자료와 맞춰 보고 써요.

## 배우기 재료
- 핵심 개념
  - **AI 를 쓰는 세 규칙**: ① 넣기 전에 개인정보를 지운다 ② 나온 결과를 원래 자료·공식 문서·실제 데이터와 맞춰 본다 ③ 쓴 것은 기록표에 적는다(맡긴 일·검증한 것·고친 것). AI 는 없는 숫자와 규격을 사실처럼 말하기도 해요(환각).
  - **Figma AI 기능**: 레이어 이름 바꾸기(Rename layers), 글자 다시 쓰기·줄이기, 이미지 만들기·고치기 같은 기능이 있고 크레딧을 써요. 계정 요금제·관리자 설정에 따라 메뉴가 안 보이거나 크레딧이 모자랄 수 있어요(Main menu 의 AI balance 로 확인). Figma Make 는 프롬프트로 시제품을 만드는 별도 파일이에요.
  - **써도 되는 곳 / 쓰면 안 되는 곳**: 배너 배경·분위기 그림·임시 이미지는 기록과 함께 써도 되지만, 실제 상품·장소 사진을 대신하거나 실제 사람 얼굴·다른 브랜드 로고를 닮게 만들거나 진짜인 척하는 리뷰 사진은 안 돼요.
- 작은 따라 하기 (사이트와 상관없이 직접 쳐요 — AI 에 아래 문장을 보내요)
  ```text
  나는 동네 도서관 앱을 디자인하는 UX 디자이너야.
  20대 대학생에게 책 찾기 경험을 묻는 인터뷰 질문 5개를 만들어 줘.
  조건: 열린 질문, 유도 질문 금지, 과거 경험을 묻기.
  → 나온 5개를 "네/아니요로 끝나나? 답을 정해 두었나? 미래를 묻나?"로 한 줄씩 검사하고,
    걸린 문장은 내가 고쳐 쓰기 → 기록표에 한 줄
  ```
- 예상해 보기: 조건에 "유도 질문 금지"라고 썼으니 5개 모두 검사를 통과할까요? — 답: 대개 한두 개는 걸려요("~하면 더 편하지 않을까요?", "앞으로 ~하실 건가요?"). AI 는 조건을 대체로 따르지만 완벽하지 않아서 검사는 내가 해요.
- 공식 문서: [Get started with Figma AI (Figma)](https://help.figma.com/hc/en-us/articles/23870272542231-Get-started-with-Figma-AI) · [Rename layers with AI (Figma)](https://help.figma.com/hc/en-us/articles/24004711129879-Rename-layers-with-AI) · [Explore Figma Make (Figma)](https://help.figma.com/hc/en-us/articles/31304412302231-Explore-Figma-Make)

| 미션 | 할 일 (고른 사이트의 구역에 맞춰 바꿔요) | 완료 기준 |
|---|---|---|
| F08-1 기본 구조 | AI 사용 기록표를 만들고, 고른 사이트 이용자용 인터뷰 질문 8개와 화면 문구 5개를 AI 로 받아 검증해요 | 기록표에 날짜·도구·맡긴 일·결과 요약·검증한 것·고친 것·최종 사용 위치 칸이 있음 / 기록 4줄 이상이고 모든 줄의 "검증한 것" 칸이 채워짐 / AI 질문 중 검사를 통과하지 못한 것을 1개 이상 찾아 고친 전·후 문장이 있음 / 프롬프트에 이름·연락처·실제 후기 원문이 없음 |
| F08-2 개념 적용 | `F08 AI 실험` 페이지에서 Figma AI 의 Rename layers 를 써 보고, 이미지 생성 AI 로 배너 배경을 만들어 검증표를 채워요 | 기본 이름(`Frame 1` 등) 레이어 4개의 실행 전·후 캡처가 있음 / 바뀐 이름 중 내 규칙(영문 소문자·하이픈)에 안 맞는 것을 직접 고침 / 배너 검증표(글자 무늬 없음·로고 닮은 것 없음·사람 얼굴 없음·글자 대비·이용 조건 허용) 5칸이 예/아니요로 채워짐 / 배너 옆에 "AI 생성 이미지" 표시와 기록표에 프롬프트 전체가 있음 |
| F08-3 응용 | 고른 사이트의 화면 하나를 Figma Make(또는 AI 가 안 보이면 다른 생성형 AI)로 시제품으로 만들고 내 시안과 기준표로 비교해요 | 화면 목적·사용자·필수 요소 3줄 요청서가 있음 / 비교표에 필수 요소 충족 여부(요소별 ✅/❌)·내 토큰 색 밖의 색 개수·글자 대비 수치가 있음 / 결과에 원본 사이트의 로고·사진이 없음 / 쓸 만한 아이디어 1개만 내 시안에 옮기고 기록표에 한 줄 |

제출: 기록표와 비교표(문서) + Figma 링크(보기 권한) 또는 캡처.

## 원본 닮음
미션마다 완료 기준 끝에 "원본 닮음" 기준을 하나 더한다. 튜터가 고른 사이트를 같은 폭으로 열어 아래 항목의 **원본 값**(칸 수·순서·자리·DevTools로 읽은 값)을 넣어 구체적으로 만든다. 사진·글은 원본 것을 쓰지 않으므로 비교하지 않는다.
- F08-1: 해당 없음 (AI 기록)
- F08-2: 해당 없음 (AI 실험)
- F08-3: 시제품과 원본을 구역 순서·배치로 비교한 표가 있음

## 힌트 재료
- 1단계: Figma 도움말 "Get started with Figma AI" — https://help.figma.com/hc/en-us/articles/23870272542231-Get-started-with-Figma-AI , 크레딧은 https://help.figma.com/hc/en-us/articles/33459875669015
- 2단계: 프롬프트에는 ① 누구를 위한 어떤 서비스인지 ② 조건(글자 수·말투·금지할 것)을 꼭 넣어요. 결과는 ① 질문은 좋은 질문 기준표 ② 문구는 글자 수를 직접 세기 ③ 규격·숫자는 공식 문서 ④ 이미지는 검증표로 검사해요. Rename layers 는 기본 이름을 쓰는 레이어만 바꾸니, 연습할 레이어는 이름을 고치지 않고 둬요.
- 3단계 예시(다른 이름·다른 값):
  ```text
  [화면 목적] 동네 도서관의 '신간 목록' 화면 시제품을 만들어 줘.
  필수 요소: 검색창, 분류 버튼 4개, 책 카드 6개(제목·저자). 모바일 375px 기준.
  색은 #0F766E, #F0FDFA, #111827 세 가지만.
  ```

## 자주 막히는 곳
- Figma 에 AI 메뉴가 안 보임 → 계정 요금제·관리자 설정·좌석 종류에 따라 달라요. 안 되면 다른 생성형 AI 로 같은 일(레이어 이름 목록 리뷰, 비교표 작성)을 하고 같은 검증을 해요
- AI 가 말한 인원수·인용이 원본과 다름 → 환각이에요. 숫자와 인용은 원본 기록에서 직접 세고 "원본과 대조"라고 검증 칸에 적어요
- 규격 설명이 공식 문서와 다름(예: "iOS 권장 터치 크기 48") → 공식 문서를 먼저 믿어요(iOS 44pt, Android 48dp)
