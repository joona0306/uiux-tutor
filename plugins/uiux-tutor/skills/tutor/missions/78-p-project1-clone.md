# 78. 프로젝트 1 · 상용 서비스 클론 — 미션 예시

> 팀 회차 — 혼자 하는 학습자용 버전

## 배우기 재료
- 핵심 개념
  - **분석 → 문제 정의 → 재설계 → 구현 → 배포 → 발표**: 디자이너가 "리뉴얼 제안"을 하는 순서 그대로예요. 근거(분석표의 캡처·인터뷰에서 나온 말)에서 문제가, 문제에서 개선안이 이어져야 해요.
  - **범위는 핵심 흐름 하나**: 서비스 전체가 아니라, 개선 포인트가 드러나는 화면 3~4개(예: 홈 → 목록(거르기) → 상세 → 장바구니 화면)만 만들어요. 로그인·결제는 화면만 만들고 버튼은 다음 화면으로 이동해요.
  - **클론은 복사가 아니에요**: 원본의 로고·사진·글은 쓰지 않아요. 가상의 이름·로고, 내가 쓴 글, 자리 표시 사진을 쓰고, 푸터와 README 에 "교육용 클론 — 원본: (사이트 이름)"을 적어요.
- 작은 따라 치기 (사이트와 상관없이 직접 쳐요. 분석표 한 줄을 `docs/analysis.md` 에 써 봐요)
  ```markdown
  | 화면 | 사용자 목표 | 첫눈에 보이는 것 | 불편한 점(근거: 캡처 번호) | 개선 아이디어 |
  |---|---|---|---|---|
  | 목록 | 마음에 드는 것 거르기 | 큰 사진 카드 | 거르기 버튼을 못 찾음 (캡처 2) | 거르기 버튼을 위로 |
  ```
- 예상해 보기: 분석표에서 "불편한 점"에 캡처 번호나 인터뷰 말을 안 적으면 발표 때 무엇이 문제일까요? — 답: 근거가 없어서 "내 느낌"이 돼요. 평가에서도 기획력은 근거 → 문제 → 개선안이 이어지는지로 봐요.
- 공식 문서: [README 정보 (GitHub Docs)](https://docs.github.com/ko/repositories/managing-your-repositorys-settings-and-features/customizing-your-repository/about-readmes) · [GitHub Pages 사이트 만들기 (GitHub Docs)](https://docs.github.com/ko/pages/getting-started-with-github-pages/creating-a-github-pages-site) · [Next.js 배포](https://nextjs.org/docs/app/getting-started/deploying)

## 원본 닮음
미션마다 완료 기준 끝에 "원본 닮음" 기준을 하나 더한다. 튜터가 고른 사이트를 같은 폭으로 열어 아래 항목의 **원본 값**(칸 수·순서·자리·DevTools로 읽은 값)을 넣어 구체적으로 만든다. 사진·글은 원본 것을 쓰지 않으므로 비교하지 않는다.
- PJ1-1: 해당 없음 (재설계라 원본과 달라도 됨 — 대신 원본의 문제와 바꾼 이유를 적음)
- PJ1-2: 원본 대신 **내 시안**과 같음 (화면마다 시안과 나란히 비교)
- PJ1-3: 해당 없음 (배포·발표)

## 힌트 재료
- 1단계: Next.js 배포 — https://nextjs.org/docs/app/getting-started/deploying , GitHub Docs README — https://docs.github.com/ko/repositories/managing-your-repositorys-settings-and-features/customizing-your-repository/about-readmes
- 2단계: 분석은 화면 하나씩 "사용자 목표 → 불편한 점 → 근거" 순서로 적어요. 구현은 공통(레이아웃·공통 컴포넌트·데이터)을 먼저, 개선 포인트가 드러나는 화면을 그다음에 만들어요. 배포는 마지막 날이 아니라 일찍 연결해 둬요. 발표 자료는 한 장에 메시지 하나, 캡처·숫자로 보여 줘요.
- 3단계 예시(다른 이름·다른 값):
  ```markdown
  # 책갈피 (교육용 클론 — 원본: ○○서점)
  - 배포 주소: https://example.vercel.app
  - 개선 포인트: 목록 위에 거르기 버튼을 두었어요 (분석표 캡처 2)
  - 원본과 다른 점: 가상 이름, 내가 쓴 글, 자리 표시 사진
  - 출처: 자리 표시 사진은 직접 만든 그림
  ```

## 자주 막히는 곳
- 범위가 끝나지 않음 → 화면 3~4개, 핵심 흐름 하나로 줄여요. 시간이 남으면 선택 기능을 넣어요
- 원본 캡처를 배포 사이트에 넣음 → 캡처는 분석 문서와 발표 비교 자료로만 써요. 배포에는 자리 표시 사진
- 발표가 기능 자랑으로 끝남 → "문제 → 근거 → 해결" 순서로 바꾸고, 시연은 개선 포인트 흐름 하나를 끝까지
