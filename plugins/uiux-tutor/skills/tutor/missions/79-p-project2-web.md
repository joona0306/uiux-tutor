# 79. 프로젝트 2 · 반응형 웹사이트 — 미션 예시

> 팀 회차 — 혼자 하는 학습자용 버전

## 배우기 재료
- 핵심 개념
  - **기획 → 디자인 → 구현 → 점검 → 배포 → 운영 데이터**: 이번에는 있는 서비스를 고치는 게 아니라 **내가 정한 주제**의 사이트를 처음부터 끝까지 만들어요. 실무에서 일하는 순서 그대로예요.
  - **기기별로 설계하기**: 시안은 모바일(375)과 데스크톱(1440)을 꼭 그리고, 배치가 크게 달라지는 페이지만 태블릿(768)을 더해요. 구현은 320·768·1280px 어디서도 깨지지 않아야 해요.
  - **데이터로 개선하기**: GA4 이벤트로 실제로 눌린 숫자를 보고, 관찰과 합쳐 작은 개선안을 쓴 뒤 같은 이벤트로 다시 확인해요.
- 작은 따라 치기 (사이트와 상관없이 직접 쳐요. `docs/responsive-plan.md` 에 기기별 구조표를 써 봐요)
  ```markdown
  | 페이지 | 모바일 375 | 태블릿 768 | 데스크톱 1440 |
  |---|---|---|---|
  | 목록 | 1열, 메뉴는 버튼 | 2열 | 3열, 메뉴 펼침 |
  | 소개 | 세로 한 줄 | (모바일과 같음) | 글·사진 두 칸 |
  ```
- 예상해 보기: 모든 페이지를 태블릿(768) 시안까지 그리면 무엇이 문제일까요? — 답: 시간이 늘어 구현·점검이 밀려요. 배치가 크게 달라지는 페이지만 768 시안을 그리고, 나머지는 모바일 규칙이 늘어난 것으로 구현해요.
- 공식 문서: [반응형 디자인 (MDN)](https://developer.mozilla.org/ko/docs/Learn_web_development/Core/CSS_layout/Responsive_Design) · [Next.js 배포](https://nextjs.org/docs/app/getting-started/deploying) · [GA4 이벤트 (Google)](https://developers.google.com/analytics/devguides/collection/ga4/events)

| PJ2-3 배포·운영 데이터 | 배포하고 GA4 이벤트 2개 이상을 심어 실제 데이터로 개선안 1~2개를 써요 | 배포 주소가 열리고 deploy.md 점검표 통과(비밀 키·`.env` 없음 포함) / 개인정보 처리방침 링크가 있음 / 실시간 보고서에서 이벤트 이름 2개가 보이는 캡처 / `docs/ga4-plan.md` 에 "숫자 + 관찰 → 개선안 → 다시 확인할 이벤트" / README 에 배포 주소·Figma 링크·점검 결과 |

## 힌트 재료
- 1단계: MDN 반응형 디자인 — https://developer.mozilla.org/ko/docs/Learn_web_development/Core/CSS_layout/Responsive_Design , Next.js 배포 — https://nextjs.org/docs/app/getting-started/deploying
- 2단계: 주제는 범위부터 줄여요(페이지 4~6개). 공통 컴포넌트·데이터·주소를 먼저 만들고, 필수 기능 → 인터랙션 → 점검 순서로 가요. 품질 점검은 마지막 날이 아니라 구현 중간에 한 번 돌려요. GA4 는 개선안을 쓰려면 며칠 데이터가 필요하니 일찍 배포해요.
- 3단계 예시(다른 이름·다른 값):
  ```markdown
  | 개선안 | 근거(숫자 + 관찰) | 다시 확인할 이벤트 |
  |---|---|---|
  | 안내 버튼을 사진 아래로 | 상세 조회 60번 중 `open_guide` 5번, 테스트 3명 중 2명이 버튼을 늦게 찾음 | `open_guide` 비율 |
  ```

## 자주 막히는 곳
- 시안과 구현이 달라짐 → 토큰(`app/tokens.css`)과 컴포넌트 이름을 시안과 같게 맞춰요
- GA4 숫자가 너무 적어 개선안을 못 씀 → 숫자 + 관찰(직접 해 본 사용성 테스트)을 함께 쓰고, 적다는 사실을 그대로 적어요. 숫자를 지어내지 않아요
- 마지막 날 배포가 깨짐 → 첫 배포를 일찍 해 두고 매 PR 마다 빌드를 확인해요
