# 77. R07. 프로젝트 준비 — 미션 예시

> 팀 회차 — 혼자 하는 학습자용 버전

## 배우기 재료
- 핵심 개념
  - **평가 근거는 기록에 남아요**: "열심히 했다"가 아니라 이슈·PR·회의록·성찰일지·AI 사용 기록·배포 주소 같은 흔적을 봐요. 혼자 하는 학습에서도 나중에 포트폴리오를 쓸 재료가 돼요.
  - **발표 뼈대**: 문제 → 근거 → 해결 → 결과 → 배운 점. 주장마다 근거를 붙여요("불편해했다" 대신 "5명 중 4명이 필터를 못 찾았다").
  - **클론은 복사가 아니에요**: 화면 구조·흐름을 분석해 다시 만드는 일이에요. 로고·사진·글을 그대로 쓰지 않고, 가상의 이름과 내가 쓴 글·자리 표시 사진을 써요. 원본 캡처는 분석 자료로만 쓰고 배포 사이트에는 넣지 않아요.
- 작은 따라 치기 (사이트와 상관없이 직접 쳐요. `docs/reflection.md` 에 오늘 일지를 한 장 써요)
  ```markdown
  # 성찰일지 — 11/24
  - 오늘 한 일: 이슈 #3 PR 머지
  - 배운 것 한 문장: 충돌은 표시를 지우고 남길 줄을 정하는 일이다
  - 막힌 것: Preview 주소가 안 열림
  - 내일 할 일: 상세 구역 반응형
  ```
- 예상해 보기: 발표에서 "사용자들이 불편해했어요"라고만 말하면 평가에서 무엇이 모자랄까요? — 답: 근거예요. 몇 명 중 몇 명, 어느 화면에서 무엇을 못 찾았는지 숫자와 장면으로 말해야 해요.
- 공식 문서: [README 정보 (GitHub Docs)](https://docs.github.com/ko/repositories/managing-your-repositorys-settings-and-features/customizing-your-repository/about-readmes) · [이슈 정보 (GitHub Docs)](https://docs.github.com/ko/issues/tracking-your-work-with-issues/learning-about-issues/about-issues)

| 미션 | 할 일 (고른 사이트의 구역에 맞춰 바꿔요) | 완료 기준 |
|---|---|---|
| P07-1 기본 구조 | 프로젝트 기간의 기록 틀을 만들어요(`docs/` 폴더에 성찰일지·AI 사용 기록·회의록 대신 쓰는 작업 메모) | `docs/reflection.md`·`docs/ai-log.md` 파일이 있음 / 성찰일지 1장(한 일·배운 것 한 문장·막힌 것·내일) / AI 사용 기록 1장에 "무엇으로 확인했나" 칸이 채워짐 |
| P07-2 개념 적용 | 평가 기준과 발표 뼈대를 내 말로 정리해요 | 평가 항목(기획력·완성도·협업·AI 활용도·발표·문서화·성찰일지)과 그 근거가 남는 곳을 표로 적음 / 2분 발표 연습 대본이 문제→근거→해결→결과 순서 / 근거 1개 이상이 숫자 또는 캡처 |
| P07-3 응용 | 프로젝트 1 대상 사이트 후보 3개를 저작권·범위 점검표로 걸러요 | 후보 3개 각각: 불편한 점 한 가지·핵심 흐름(화면 3~4개)·로그인·결제 없이 화면만으로 가능한지·우리 사이트의 가상 이름 / 원본 사진·글·로고를 배포에 쓰지 않는다는 계획 한 줄 / 후보 1개 선택과 이유 한 줄 |

## 원본 닮음
미션마다 완료 기준 끝에 "원본 닮음" 기준을 하나 더한다. 튜터가 고른 사이트를 같은 폭으로 열어 아래 항목의 **원본 값**(칸 수·순서·자리·DevTools로 읽은 값)을 넣어 구체적으로 만든다. 사진·글은 원본 것을 쓰지 않으므로 비교하지 않는다.
- P07-1: 해당 없음 (기록 틀)
- P07-2: 해당 없음 (평가 기준)
- P07-3: 해당 없음 (후보 거르기)

## 힌트 재료
- 1단계: GitHub Docs README — https://docs.github.com/ko/repositories/managing-your-repositorys-settings-and-features/customizing-your-repository/about-readmes
- 2단계: 후보를 고를 때는 "화면 3~4개로 보여 줄 수 있나"와 "로그인·결제 없이 되나"를 먼저 봐요. 큰 서비스는 화면 하나(핵심 흐름 하나)만 골라요.
- 3단계 예시(다른 이름·다른 값):
  ```markdown
  | 후보 | 분야 | 불편한 점 | 핵심 흐름 | 화면만으로 가능? | 저작권 점검 |
  |---|---|---|---|---|---|
  | 동네 서점 앱 | 커머스 | 책 거르기가 어려움 | 홈→목록→상세 | 예 | 가상 이름 "책갈피", 자리 표시 사진 |
  ```

## 자주 막히는 곳
- 후보가 너무 큼 → 서비스 전체가 아니라 핵심 흐름 하나(화면 3~4개)가 범위예요
- 성찰일지가 "열심히 함" → 이슈·PR 번호와 배운 것 한 문장으로 바꿔요
- AI 사용 기록의 확인 칸이 비어 있음 → build 통과·lint 0·키보드처럼 무엇으로 확인했는지를 적어요
