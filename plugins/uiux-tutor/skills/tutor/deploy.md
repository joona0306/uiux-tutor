# 배포 — 언제, 무엇으로

만든 클론을 인터넷에 올려 **주소로 보여 줄 수 있게** 하는 단계예요. 배포는 학습자가 직접 한다(튜터는 명령을 실행하지 않고, 순서와 점검만 돕는다).

## 언제 배포하나

| 단계 | 진도표 회차 | 도구 | 올리는 것 | 왜 이때 |
|---|---|---|---|---|
| 배포 ① | 47. Day 10 GitHub | **GitHub Pages** | 지금까지 만든 HTML·CSS·JS 클론 | Git·GitHub를 배운 날. 빌드가 필요 없는 정적 파일이라 저장소 설정만으로 올라가요 |
| 배포 ② | 66. Day 24 Vercel | **Vercel** | Next.js로 옮긴 클론 | Next.js는 빌드가 필요해요. Vercel은 GitHub 저장소와 연결해 push할 때마다 다시 배포해요 |
| 배포 ③ | 75. R05 개인 실습 | Vercel | 완성한 클론 + README(배포 주소·만든 것·원본과 다른 점) | 포트폴리오로 쓸 결과물 |

- 범위에 Day 10 이 없는 학습자(예: React부터 시작)는, 범위의 **첫 Next.js 회차**나 마지막 회차에서 배포 ②를 한다.
- React(Vite) 단계 결과물을 올리고 싶으면 Vercel로 올릴 수 있다(빌드 명령 `npm run build`, 결과 폴더 `dist`). 이것은 선택 미션.

## 배포 전 점검 (모든 단계 공통 — 완료 기준에 넣는다)
- [ ] 원본 사이트의 사진·글·로고가 없다(자리 표시 사진, 내가 쓴 글)
- [ ] 화면에 **"교육용 클론 — 원본: (사이트 이름)"** 표시가 있다
- [ ] 사이트·저장소 이름이 원 서비스 이름이 아니다
- [ ] 저장소에 비밀 키·`.env` 파일이 없다(`git status`, GitHub 화면에서 확인)
- [ ] 공공 데이터 사진을 썼다면 출처 표시가 있다(공공누리 유형 지키기)
- [ ] 배포 주소를 휴대폰 폭(375px)과 PC 폭에서 열어 봤다

## 평가할 때
- 배포 주소를 받아 Chrome으로 연다. 375·1024px에서 보고, 위 점검을 근거와 함께 판정한다.
- 배포가 실패했으면 학습자가 붙인 오류 문구(GitHub Pages 설정 화면, Vercel 빌드 기록)를 읽고 원인만 짚는다.
