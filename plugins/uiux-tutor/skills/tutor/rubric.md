## 판정 기준
- ✅ 통과: 기준을 만족하고 근거(파일:줄 또는 실행 결과)가 있다.
- 🔧 보완: 기준을 못 맞췄거나, 맞췄는지 **확인할 수 없다**. 확인할 수 없으면 무엇을 보여 주면 되는지 말한다(예: "브라우저 폭 640px 화면 캡처").
- **원본 닮음**은 원본과 학습자 페이지를 같은 폭으로 직접 열어 본 뒤에만 ✅ 를 준다. 근거에 양쪽 값을 함께 적는다. 코드만 읽고는 ✅ 를 주지 않는다.
- **흐름 닮음**은 원본과 내 사이트를 같은 순서로 눌러 본 뒤 단계별 표로 판정한다. 한 단계라도 화면 구성·진입점·상태가 다르면 🔧 다.
- 미션과 상관없는 다른 문제는 판정에 넣지 않고 "덧붙임"으로 한 줄만 적는다. (단, 아래 **기본 점검**은 매번 판정한다.)

## 기본 점검 — 접근성·웹표준·SEO (회차 4부터, 매 평가)
완료 기준 표 맨 아래에 "기본 점검" 한 줄을 늘 더한다. 미션 기준이 아니어도 웹 페이지라면 지켜야 하는 것이라, 🔧 이면 그 미션도 보완이다.
- **범위**: 이번 미션에서 학습자가 만들거나 고친 파일·구역만 본다(다른 곳의 문제는 "덧붙임" 한 줄). Figma 회차(22~29)와 Git 회차(46·48)는 하지 않는다.
- **방법**: 파일을 읽어 파일:줄로 근거를 단다. 키보드 항목은 튜터 탭에서 Tab 키로 직접 해 본다(SKILL.md 4절 "학습자 페이지 열기"). 해 보지 못한 항목은 "확인 못 함"으로 적고 🔧 로 치지 않는다 — 대신 무엇을 보여 주면 되는지 말한다.
- **항목** (배운 회차부터 더해진다):

| 회차부터 | 항목 |
|---|---|
| 4 (W04) 접근성·표준 | 모든 `<img>` 에 `alt`(장식 그림은 `alt=""`) · 제목 단계를 건너뛰지 않음(`h1` → `h2` → `h3`) · 링크·버튼 글자만 읽어도 무엇인지 앎(빈 링크, "여기"·"클릭" 없음) · `<html lang="ko">` · 같은 `id` 두 번 없음 · 닫는 태그 빠짐·잘못된 겹침 없음 |
| 4 (W04) SEO | `<title>` 이 페이지 내용을 말함(페이지마다 다름) · `<meta name="description">` 에 페이지 요약 1~2문장(비어 있지 않음) |
| 5 (W05) | 입력칸마다 `<label>` 이 짝(`for`·`id` 또는 감싸기) · 누르는 것은 `<button>`·`<a>`(클릭되는 `div` 없음) |
| 20 (W20) | `outline: none` 으로 포커스 표시를 지우지 않음 · 이번 미션의 링크·버튼·메뉴를 Tab·Enter 로 쓸 수 있음 |
| 37 (JS 인터랙션) | 열고 닫는 것(메뉴·탭·아코디언·모달)의 `aria-expanded`·`aria-selected` 가 화면 상태와 같이 바뀜 |
| 49 (React) 이후 | 위 항목을 JSX에서도 같게 본다(`className`, `htmlFor`) |
| 63 (Next) 이후 SEO | 페이지마다 `metadata` 또는 `generateMetadata` 로 `title`·`description` 이 있음 |

- 한 번에 보완할 점 3개 이하 규칙은 기본 점검에도 적용한다. 많으면 접근성(그림 `alt`·`label`·키보드) → 표준 → SEO 순으로 고르고, 나머지는 다음 평가로 넘긴다.
- 같은 항목이 두 번 넘게 🔧 이면 진도 파일 `weak` 에 그 항목(예: "alt", "label")을 더한다.

## 말투
- 고칠 곳은 **위치와 이유**까지만. 고친 코드는 주지 않는다(학습자가 "정답 보여 줘"라고 할 때만).
- 한 번에 보완할 점은 3개 이하. 많으면 가장 중요한 것부터.
- 시도가 3번을 넘으면 개념 설명을 한 번 더 하고, 미션을 두 조각으로 나눠 준다.
